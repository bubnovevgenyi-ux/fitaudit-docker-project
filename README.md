# FitAudit — React-калькулятор КБЖУ

Веб-приложение для поиска продукта в каталоге FitAudit и отображения калорийности, белков, жиров и углеводов. Значения исходной карточки берутся на 100 г; поле веса порции пересчитывает показатели пропорционально массе.

## Запуск в Docker (рекомендуемый способ)

Требования: установленный Docker Engine с Docker Compose Plugin или Docker Desktop.

1. Распакуйте проект.
2. Откройте терминал в корневой папке проекта, где находится `docker-compose.yml`.
3. Выполните:

```bash
docker compose up --build -d
```

После сборки приложение будет доступно по адресу:

- `http://localhost:3001` — веб-интерфейс;
- `http://localhost:3001/api/health` — проверка API.

Вместе с приложением поднимается контейнер `mongo` (MongoDB 7), в котором хранятся любимые блюда. Данные сохраняются в именованном томе `mongo-data` и переживают перезапуск контейнеров.

Посмотреть логи:

```bash
docker compose logs -f fitaudit
```

Остановить контейнер:

```bash
docker compose down
```

Повторная сборка после изменения исходного кода:

```bash
docker compose up --build -d
```

### Изменение внешнего порта

По умолчанию порт хоста — `3001`. Чтобы открыть приложение, например, на `8080`, выполните:

```bash
APP_PORT=8080 docker compose up --build -d
```

В Windows PowerShell:

```powershell
$env:APP_PORT="8080"; docker compose up --build -d
```

В этом случае интерфейс будет доступен по адресу `http://localhost:8080`.

### Запуск без Compose

```bash
docker build -t fitaudit-calculator .
docker run --rm -p 3001:3001 --name fitaudit-calculator fitaudit-calculator
```

## Запуск локально без Docker

Необходим Node.js 18.18+ и npm.

```bash
npm install
npm --prefix client install
npm run dev
```

Откройте `http://localhost:5173`. Vite проксирует запросы `/api/*` на Express-сервер `http://localhost:3001`.

Production-сборка без Docker:

```bash
npm install
npm --prefix client install
npm run build
npm start
```

## Автоматические тесты

Тесты проверяют извлечение названия и идентификатора продукта из каталога, разбор калорийности и БЖУ из HTML-карточки, обработку десятичной запятой/точки, отказ при неполных данных, поиск по названию и ответы HTTP API.

Тесты используют локальные HTML-фикстуры и подменённые функции загрузки. Во время тестирования запросы к FitAudit не выполняются.

Локальный запуск из корня проекта (достаточно установить серверные зависимости командой `npm install`):

```bash
npm test
```

Запуск в режиме наблюдения за изменениями тестов:

```bash
npm run test:watch
```

Dockerfile выполняет `npm test` на отдельном этапе сборки. Поэтому команда `docker compose up --build -d` не создаст production-образ, если любой тест завершится ошибкой.

Повторный запуск тестов в уже собранном образе:

```bash
docker compose run --rm --no-deps fitaudit npm test
```

Набор состоит из двух файлов:

- `server/fitaudit.test.js` — unit-тесты парсинга каталога, карточки продукта и поиска;
- `server/app.test.js` — интеграционные тесты API `/api/health`, `/api/search` и `/api/products/:id`, включая проверки кеша и ошибок источника.

## API приложения

- `GET /api/search?q=куриная` — поиск по каталогу и список подходящих продуктов.
- `GET /api/products/102620` — данные конкретной карточки продукта (КБЖУ, клетчатка, B12, Омега-3, Омега-6).
- `GET /api/health` — проверка работы API.

Страница «Каталог продуктов» открывается кнопкой в верхней панели главной страницы; из каталога кнопка «Калькулятор» возвращает на главную. Таблица показывает КБЖУ на 100 г, поддерживает поиск по названию и серверную пагинацию по 20 записей.

API каталога продуктов (хранится в MongoDB):

- `GET /api/catalog?q=кефир&limit=20&skip=0` — список продуктов из каталога (поиск по названию и постраничная выдача; `total` содержит полное число найденных записей).
- `POST /api/catalog/import` — импортировать каталог FitAudit в MongoDB. Тело: `{ limit, concurrency, delayMs }` (все поля необязательны).

Карточка продукта содержит поля `calories`, `protein`, `fat`, `carbs` (на 100 г), а также `fiber` (клетчатка, г), `b12` (мкг), `omega3` и `omega6` (г). Омега-3 — сумма альфа-линоленовой (ALA), тимнодоновой (EPA) и докозапентаеновой (DPA) кислот; Омега-6 — сумма линолевой, гамма-линоленовой, эйкозадиеновой и арахидоновой кислот. Значения «н/д» (нет данных) в сумму не входят.

API любимых блюд (хранится в MongoDB):

- `GET /api/dishes` — список сохранённых блюд.
- `POST /api/dishes` — создать блюдо (`{ name, components: [...] }`).
- `GET /api/dishes/:id` — получить одно блюдо.
- `PUT /api/dishes/:id` — обновить название и компоненты блюда.
- `DELETE /api/dishes/:id` — удалить блюдо.

Компонент блюда имеет вид `{ id, name, grams, sourceUrl, per100: { calories, protein, fat, carbs } }`; сервер пересчитывает КБЖУ компонента на фактический вес и суммирует итоговые значения.

## Структура Docker-образа

Используется многоэтапная сборка:

1. На этапе `client-build` устанавливаются клиентские зависимости и собирается React-приложение через Vite.
2. В итоговый образ копируются Express-сервер, production-зависимости и статические файлы React.
3. Приложение запускается одним Node.js-процессом на порту `3001` от непривилегированного пользователя `node`.

Docker Compose публикует порт контейнера `3001` на порт хоста `APP_PORT` (по умолчанию `3001`). Сборка фронтенда и backend находятся в одном контейнере — отдельный reverse proxy для локального запуска не требуется. MongoDB работает в отдельном контейнере `mongo`; приложение подключается к нему через `MONGODB_URI`.

## Как устроено получение данных

1. Сервер получает HTML-каталог `https://fitaudit.ru/food` и извлекает ссылки вида `/food/{id}`.
2. Каталог кешируется в памяти сервера на 6 часов, чтобы не обращаться к FitAudit при каждом символе.
3. После выбора пользователем результата сервер ищет карточку в MongoDB, а при отсутствии загружает страницу продукта (основную и страницу «Жиры»), извлекает КБЖУ, клетчатку, B12, Омега-3 и Омега-6, сохраняет в MongoDB и кеширует в памяти на 24 часа.
4. React получает структурированный JSON и пересчитывает показатели для указанного веса порции.

### Импорт каталога в MongoDB

Каталог наполняется автоматически при запросе конкретного продукта, а также его можно заполнить целиком:

```bash
# после того как контейнеры запущены (docker compose up -d)
docker compose exec fitaudit node server/importCatalog.js
```

Для ограничения объёма импорта можно задать переменные окружения `IMPORT_LIMIT`, `IMPORT_CONCURRENCY`, `IMPORT_DELAY_MS` (например, `docker compose exec -e IMPORT_LIMIT=100 fitaudit node server/importCatalog.js`). Частичный импорт также доступен через `POST /api/catalog/import` с параметром `limit`.

В обнаруженной структуре сайта отдельный документированный API поиска не используется: интеграция читает HTML-страницы. Если FitAudit изменит разметку, парсер `server/fitaudit.js` потребуется адаптировать. Доступность запросов зависит от доступности сайта и его правил использования; перед публичным или коммерческим развёртыванием проверьте условия FitAudit и допустимую частоту автоматических запросов.
